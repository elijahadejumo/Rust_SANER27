# Engagement, Affect, and Governance Debt in Rust Request for Comments

Paper source and replication package for a study of Rust Request-for-Comments (RFC) discussions:

- **RQ1:** How do engagement and affect differ across accepted, rejected, and postponed RFCs?
- **RQ2:** Are signs of postponement visible early in deliberation?

## Layout

| Path | Contents |
|---|---|
| `paper/` | LaTeX source of the paper |
| `data/` | Input corpus (described below) |
| `collection/collect_rfc_comments.py` | Collects PR comments from the GitHub REST API (needs `GITHUB_TOKEN`) |
| `scoring/` | Sentiment scoring script and emotion scoring notebook |
| `analysis/corpus.py` | Shared code: outcome labels, measures, statistics |
| `analysis/rq1_outcome_profile.py` | RQ1 analysis |
| `analysis/rq1_matched_pairs.py` | RQ1 robustness: within-author matched pairs |
| `analysis/rq2_early_window.py` | RQ2 analysis |
| `analysis/make_figures.py` | Paper figures (needs matplotlib), written to `paper/figures/` |
| `results/rq1/`, `results/rq2/` | Outputs of the two analyses |

## Reproducing the results

The analysis scripts need only Python 3 (standard library). Run them from the repository root:

```
python3 analysis/rq1_outcome_profile.py data results/rq1
python3 analysis/rq1_matched_pairs.py   data results/rq1
python3 analysis/rq2_early_window.py   data results/rq2
python3 analysis/make_figures.py      results paper/figures   # needs matplotlib
```

### RQ1 outputs (`results/rq1/`)

| File | Contents |
|---|---|
| `rq1_summary.txt` | Readable summary of the tables below |
| `rq1_review_duration.csv` | Review Duration (days from PR opening to decision): median, mean, quartiles, and IQR by outcome |
| `rq1_profile.csv` | Engagement metrics, tone, and all 28 emotions, by outcome |
| `rq1_rfc_features.csv` | One row per RFC with every measure, for figures |
| `rq1_matched_pairs.csv`, `rq1_matched_pairs_summary.txt` | Within-author Wilcoxon signed-rank tests, in two designs. `author_median` compares each author's median over their proposals with each outcome, as in the original study. `time_matched` pairs each author's two proposals (one per outcome) that were submitted closest in time. Both designs are run for every outcome pair. |

### RQ2 outputs (`results/rq2/`)

| File | Contents |
|---|---|
| `rq2_summary.txt` | Readable summary of the tables below |
| `rq2_windows.csv` | Results for the 30- and 60-day windows, for two populations: `ALL` (every RFC) and `AT_RISK` (only RFCs still undecided when the window ends) |
| `rq2_same_cohort.csv` | RFCs still undecided at day 60, measured at day 30 and again at day 60 |
| `rq2_rfc_features.csv` | One row per RFC still undecided at each window, with its early-window measures (for figures) |

Every results table reports, for each outcome group, n, median, and mean. Each pairwise comparison has three columns: rank-biserial r, raw p, and Benjamini-Hochberg-adjusted p (`p_bh_*`). BH adjustment is applied within each table: across all measures in the RQ1 profile, per design and outcome pair in the matched pairs, and per window and population in RQ2.

## Data

- `rfc_accepted.csv`: accepted (merged) RFC proposals, one row per RFC.
- `rfc_rejected.csv`: closed proposals, with outcome `rejected`, `postponed`, or `withdrawn`, plus their GitHub labels.
- `rfc_comments_full.csv`: every PR comment, with author, timestamp, and body. The analysis filters out bots.
- `rfc_roberta_scores.csv`: sentiment for each comment. `rob_score` is P(positive) − P(negative), in [−1, 1].
- `rfc_goemotions_scores.csv`: probabilities for the 28 GoEmotions categories for each comment.
- `rfc_sentiment_3class_scores.csv`: robustness check, with sentiment for each comment from a three-class model (`cardiffnlp/twitter-roberta-base-sentiment-latest`), which includes a neutral class. It is generated by `scoring/score_sentiment.py`. The analyses report it as `tone_3class`.

## Analysis decisions

- **Outcome labels.** A merged PR counts as accepted. A closed PR with the `postponed` label counts as postponed, and any other closed PR counts as rejected.
- **Exclusions.** The analysis drops:
  - 18 withdrawn PRs;
  - 36 PRs labelled `not-rfc` or `april-1st`;
  - 3 PRs whose rfcbot disposition label conflicts with their outcome (#3035, #3469, #3505);
  - 15 accepted RFCs that have no PR creation or merge date.

  PR #2071 carries two accepted RFC numbers and is counted once. **Analyzed: 609 accepted, 758 rejected, 102 postponed (1,469 RFCs).**
- **Scope.** RQ1 uses each proposal's whole discussion: every human comment on its PR, including those posted during and after the formal decision. RQ2 uses only the comments posted in the first 30 or 60 days after submission.
- **Engagement metrics** (definitions as in the paper; the column name in the results is in parentheses):
  - Review Duration (`review_duration_days`): days from PR creation to merge or close.
  - Unique Commenters (`unique_commenters`), plus the number of comments (`n_comments`).
  - Influence Score (`influence_score`): the sum of the commenters' prospective degrees. A person's prospective degree is the number of distinct RFCs they had commented on before the focal RFC was opened.
  - Echo Score (`echo_score`): the fraction of commenters in the governance core. The core is the k participants with the highest prospective degree when the RFC was opened, with k = the median Unique Commenters over all proposals (k = 10, computed by the code).
  - First Commenter Degree (`first_commenter_degree`, RQ1 only): the prospective degree of the first commenter.
- **Affect.** For each RFC, the mean over the comments in scope of three things:
  - sentiment (`tone`);
  - the three-class robustness sentiment (`tone_3class`);
  - each GoEmotions category.
- **Bots excluded.** rfcbot, rust-highfive, bors, bors-servo, rust-rfcbot, rustbot, renovate[bot].
- **Tests.** Pairwise two-sided Mann-Whitney U tests (normal approximation with tie correction).

## Scoring models

- **Sentiment:** `siebert/sentiment-roberta-large-english` (Hartmann et al., 2023), used as published with no further training. `scoring/score_sentiment.py` generates `data/rfc_roberta_scores.csv`. A check on a random sample of 300 comments reproduced the file: all 300 got the same label, and scores differed by at most 0.0002.
- **Emotion:** `monologg/bert-base-cased-goemotions-original`, in `scoring/rq2_goemotions_colab.ipynb`. It was run in Google Colab, with input files under `/content/`.

`score_sentiment.py` needs `torch` and `transformers`. Example:

```
python3 scoring/score_sentiment.py --model siebert/sentiment-roberta-large-english \
    --comments data/rfc_comments_full.csv --out data/rfc_roberta_scores.csv
```
